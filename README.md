# AeroPilot

## Онлайн-соревнования (Supabase)

Соревнования используют отдельную авторизацию Supabase. Демо-аккаунты и результаты из LocalStorage не участвуют в сетевых матчах. В репозитории есть миграция и клиентская интеграция, но для запуска нужен собственный Supabase-проект:

1. Создай проект Supabase и включи Email в **Authentication → Providers**. Для простого локального теста можно отключить подтверждение email; для рабочего запуска настрой подтверждение и адрес сайта/redirect URLs в **Authentication → URL Configuration**.
2. Примени `supabase/migrations/20261030000000_competitions.sql` через Supabase CLI (если конфигурации CLI ещё нет: `supabase init`, затем `supabase link` и `supabase db push`) или SQL Editor. Миграция создаёт профили, комнаты, вопросы, RPC с проверкой ответов и включает публикацию изменений комнат в Supabase Realtime.
3. В `supabase-config.js` укажи Project URL и **publishable/anon key** из Project Settings → API. Этот ключ предназначен для браузера; **никогда не добавляй service_role key** в клиент.
4. Размещай приложение через HTTP(S) с поддержкой ES modules (например, локально через Live Server). Создай два разных аккаунта Supabase и открой приложение в двух браузерах/профилях.
5. Проверь сценарий: игрок A создаёт комнату или запускает быстрый поиск, игрок B принимает приглашение/вводит код, оба отмечают готовность, отвечают на пять одинаковых вопросов, видят прогресс друг друга, затем сервер фиксирует победу/ничью, XP и изменение рейтинга. Для реконнекта достаточно снова открыть «Соревнования»: состояние загружается с сервера, а во время матча дополнительно обновляется через Realtime.

Сейчас полностью серверно реализована **теоретическая дуэль**. Полётная дуэль, посадка на точность и экзамен пилота намеренно не имитируются викториной: для безопасного результата нужна серверная детерминированная проверка телеметрии/событий симулятора, которой в текущем проекте нет. Эти режимы обозначены в интерфейсе как недоступные, пока такая проверка не появится.

Результаты нельзя записать напрямую через клиентские таблицы: ответы принимаются только RPC, правильность вычисляет PostgreSQL, а RPC завершения обновляет XP, рейтинг и победителя в одной транзакции. Ответы закрыты от прямого чтения, прогресс для Realtime агрегируется сервером.

Без конфигурации Supabase существующая локальная академия продолжает работать; онлайн-раздел сообщает, что backend не настроен, и не создаёт фиктивного соперника.

## Конструктор курсов

Конструктор — отдельный раздел приложения. Курсы, настройки блоков, связи и ветви сохраняются как черновики в `LocalStorage` этого браузера и профиля; материалы файлов в браузерное хранилище не помещаются.

Чтобы загружать изображения, PDF, видео и аудио, настрой Supabase URL и publishable/anon key в `supabase-config.js`, войди через Supabase Auth и примени миграции по порядку, включая `supabase/migrations/20261031000000_course_materials.sql`. Она создаёт закрытый bucket `course-materials` (50 МБ на файл) и политики доступа, ограниченные папкой пользователя. Для этого нужны права Supabase Storage; service-role ключ в клиенте не используется.

В редакторе блоки добавляются из левой панели или перетаскиваются на поле. Выбери порт «Далее», «Да» или «Нет», затем целевой блок; переходы можно также менять в настройках блока. Предпросмотр исполняет эти связи, автоматически проверяет тесты и выбирает ветку по порогу. Блок практики проверяется по факту завершения соответствующей существующей миссии; симулятор остаётся отдельной работающей функцией.

Проверка логики: `node --test tests\\course-engine.test.mjs tests\\lesson-engine.test.mjs`. Облачную загрузку и межустройственную синхронизацию нельзя проверить без своего Supabase-проекта и двух реальных аккаунтов.
